# Evaluation goal

Evaluate how much an AI item helps a reader who already uses AI tools daily **do something concrete**: adopt a tool, change a workflow, cut a cost, or avoid a known failure. Not how impressive the announcement sounds.

# Scoring rubric

- **9-10: 立刻可用或必须调整。** 已发布且可立即使用的重要能力变化：某主流模型新增关键能力（长上下文、可靠工具调用、结构化输出）并公布价格；某常用工具大幅降价或改为免费额度；MCP 等协议出现被广泛采纳的新标准；一个可直接部署的开源 Agent 框架发布且文档完整；有实测数据证明某工作流效率提升数倍。
- **7-8: 高价值。** 有具体用法和数字的实践：带成本对比的落地案例、详细的 Agent 架构取舍分析、可靠的工具调用技巧、可复现的评测结果揭示某模型在具体任务上的真实短板、重要开源项目的大版本更新（含迁移说明）。
- **5-6: 值得了解。** 有价值的增量信息：新模型发布但能力提升有限、某工具的体验改进、单个团队的实践经验但样本较小、某 API 的价格小幅调整。
- **3-4: 低优先级。** 只有宣传没有细节的发布、重复报道已广为人知的消息、浅尝辄止的工具测评、没有数据支撑的经验分享。
- **0-2: 噪音。** 融资估值新闻、纯提示词清单、无证据的趋势预测、入门科普、AI 生成作品展示、营销活动。

# Evaluation guidance

评估时依次问：

1. **有没有可执行的信息？** 能不能据此改一行配置、换一个模型、改一段代码？有具体参数、价格、仓库地址、版本号的加分。
2. **有没有数字？** token 成本、延迟、准确率、节省时间、并发上限。纯形容词描述（「更快」「更强」「更便宜」）降 2 分。
3. **能不能复现？** 提到的方法是否有代码、配置、公开数据支撑。只有结论没有过程的降 2 分。
4. **是不是真的新的？** 与三个月前相比有什么变化？重复已知信息的降 2 分。

**特别警惕 benchmark 数字**：必须看它测的是什么任务、什么条件、与谁对比。一个模型在某私有 benchmark 上高 2 分，可能在实际使用中毫无区别。若文中只给总分不给任务细节，降 2 分。

**区分「演示」和「可用」**：一段 demo 视频展示 Agent 完成了任务，不等于这个 Agent 在真实场景下可靠。已上线、有公开文档和价格的产品 > 等待名单 > 演示视频。

**对成本敏感**：读者是个人开发者或小团队，月成本 20 美元和 200 美元是不同量级的决策。文中给出实际花费的加分。

Use three to five specific topic tags，优先使用这些之一：`模型发布`、`Agent框架`、`工具实测`、`成本优化`、`开源项目`、`工作流`、`能力边界`、`协议标准`。
